# 터미널 진행률 및 결과 표 구현 설계

## 화면 동작

| 출력 대상 | ANSI를 지원하는 터미널 | 파일, 파이프, 일반 터미널 |
| --- | --- | --- |
| `stderr` 진행 상태 | 탐색 중에는 발견 수, 처리 중에는 청록색 막대와 완료 수 및 백분율 | 기본 실행에서는 생략. `--verbose`에서는 기존 텍스트 로그 출력 |
| `stdout` 작업 요약 | 작업 상태별 건수와 전체 건수를 한 표로 출력 | 기존 `Summary updated=… planned=… skipped=… failed=…` 한 줄 출력 |

진행률은 작업 결과와 관계없이 처리 완료 수를 기준으로 계산한다. 저장소가 0개면 `0/0 processed · 100%`와 전체 건수 0을 표시한다. 빈 결과 안내, 경로별 결과, 상세 로그 위치, 종료 코드는 기존 동작을 따른다.

표에서 `Updated`는 초록, `Planned`는 파랑, `Skipped`는 노랑, `Failed`는 빨강으로 표시한다. 값은 오른쪽 정렬하며 자릿수가 늘어나면 열 너비도 늘린다. 비어 있지 않은 `NO_COLOR`가 설정되면 막대와 표의 레이아웃을 유지하고 색상을 끈다.

## 코드 구성

- `Cli.Progress`는 탐색 및 처리 상태를 전달한다. `Cli.Render`는 기존 일반 텍스트 렌더러와 함께 터미널 막대와 표를 그린다.
- `Main`은 `Infrastructure.Terminal`의 기존 플랫폼별 감지를 재사용해 `stdout`과 `stderr`의 터미널 기능을 각각 확인한다. 새 의존성 없이 구현한다.
- 출력은 기존 진행 상태 갱신 방식과 결과 집계를 재사용한다.

## 구현 및 검증 순서

1. CLI 인수 테스트에서 터미널 색상과 상태별 건수, `NO_COLOR`, 빈 입력, 개별 스트림 리다이렉션을 확인하도록 한다. 현재 실행 파일에서 새 출력 검사가 실패하는 것을 확인한다.
2. 진행 상태 전달 및 렌더링을 구현한다. 각 스트림의 터미널 감지 결과를 연결하고 기존 텍스트 출력을 검증한다.
3. README에 출력 형식을 설명하고 `cabal test all`과 `git diff --check`를 실행한다.
